# 05_data_flow.md  
## データ取得・更新の流れ（ver.2）

---

## 🧭 1. 全体データフロー概要

本アプリは「ユーザー操作」と「日次更新処理」によってデータを扱う。  
主要な流れは以下の2種類：

1. **路線登録フロー**（ユーザーが新しい便を登録）  
2. **日次記録フロー**（毎日価格を追加記録）

---

## ✈️ 2. 路線登録フロー

### 処理の流れ

```

[ユーザー入力]
↓
[Next.js フロント]
↓ POST /api/routes
[Go バックエンド]
↓ INSERT INTO flight_route
[PostgreSQL]

````

### 詳細ステップ

1. ユーザーが「出発地」「到着地」「航空会社」「出発日」などを入力  
2. フロントが `/api/routes` にPOST（JSON送信）  
3. Goサーバーでバリデーション（重複チェック）  
4. DBの `flight_route` テーブルに登録  
5. 登録結果をJSONで返却 → フロントで確認表示

### サンプルリクエスト
```json
POST /api/routes
{
  "departure": "HND",
  "arrival": "CTS",
  "airline": "ANA",
  "departure_date": "2025-12-01",
  "transit": "",
  "memo": "冬旅"
}
````

## 📅 3. 日次記録フロー（手動／自動）

### 処理の流れ

```
[ユーザー操作 or 自動スケジュール]  
   ↓  
[Next.js → /api/prices/add]  
   ↓  
[Go バックエンド]
   ↓ INSERT or UPDATE price_history  
[PostgreSQL]
```

### 詳細ステップ

1. 登録済みの便一覧から対象を選択
2. その日の販売価格を入力（手動）
3. フロントが `/api/prices/add` にPOST
4. Goサーバーが `(route_id, record_date)` の存在を確認

   * 存在しなければ `INSERT`
   * 存在すれば `UPDATE`
5. DB更新後、最新価格を返却

### 将来的な自動化（構想）

* CronまたはSupabase Functionsを利用して1日1回トリガー
* 事前に登録された「参照URL」から価格を取得
* スクレイピング／API取得で `price_history` に自動追記

## 📊 4. 表示・可視化フロー

```
[ユーザー画面（Next.js）]
   ↓ GET /api/routes
   ↓ GET /api/prices/:route_id
[Go API]  
   ↓ SELECT文でデータ取得  
   ↓ 整形JSONを返却  
[Next.jsで描画（グラフ／カレンダー）]
```

### 主な表示形式

| 表示種別   | 説明                      |
| ------ | ----------------------- |
| 折れ線グラフ | 価格の時系列変化（record_dateごと） |
| ヒートマップ | 出発日×購入日の価格比較            |
| カレンダー  | 出発日別に便を配置して比較           |

### データ例（フロント受け取り形式）

```json
{
  "route": {
    "id": 3,
    "departure": "HND",
    "arrival": "CTS",
    "airline": "ANA",
    "departure_date": "2025-12-01"
  },
  "prices": [
    { "record_date": "2025-11-01", "price": 16200 },
    { "record_date": "2025-11-02", "price": 16780 },
    { "record_date": "2025-11-03", "price": 17520 }
  ]
}
```

## 🕒 5. データ更新スケジュール（想定）

| 処理    | タイミング    | 実装方法                          |
| ----- | -------- | ----------------------------- |
| 手動記録  | 任意       | フロント操作（ボタン）                   |
| 自動記録  | 毎日 09:00 | Cronジョブ or Supabase Functions |
| データ整理 | 毎週       | 古い履歴削除（>90日）                  |

---

## 🔁 6. エラーハンドリング方針

| 事象       | 対応方法                   |
| -------- | ---------------------- |
| 同一路線重複登録 | バリデーションで登録拒否           |
| 価格未入力    | エラーメッセージ表示             |
| API通信失敗  | 再試行3回／オフライン保存対応予定      |
| DB接続失敗   | リトライ＋ログ出力              |
| 無効な日付    | 入力時点でバリデーション（Next.js側） |

---

## 🧮 7. データ整合性ルール

* `flight_route.id` と `price_history.route_id` はFKで常に紐付く
* 1日1価格記録を原則（`UNIQUE(route_id, record_date)`）
* 出発日が過ぎた便は編集不可（参照のみ）
* 更新操作は必ず`updated_at`を変更して記録
